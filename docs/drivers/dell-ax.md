## DISM injection

The build script injects all drivers recursively via DISM:

```powershell title="From Build-WinPEImage.ps1 (simplified)"
dism /Image:<mount> /Add-Driver /Driver:drivers\dell-ax /Recurse
```

All drivers are signed (`.cat` catalog included), so no `/ForceUnsigned` flag is needed.

## Updating drivers

To update to a newer SBE bundle:

1. Download the new SBE zip from Dell/Azure Local update channel
2. Extract `DriversGE\Network\` into the five `drivers/dell-ax/` subdirectories, replacing existing files
3. Update the version table in this document and regenerate the manifest: `pwsh scripts/New-DriverManifest.ps1`
4. Rebuild the ISO

> [!TIP]
> **Dell firmware (not included)**
> The SBE bundle also contains network firmware DUPs (Broadcom FW 36.11.56.00, Mellanox ConnectX FW 26.41.10.00, Intel E810 FW 23.61.3). These are not injected into the Beacon image — firmware updates are applied through Dell SBE / Cluster-Aware Updating during the cluster update lifecycle.

## Driver manifest

`drivers/driver-manifest.json` lists every bundled driver file with its size and SHA256, and for every INF the provider, class and
`DriverVer`, plus where each set came from. It is generated by `scripts/New-DriverManifest.ps1`; a test compares it with the
files on disk, so a driver that changes without the manifest changing fails CI. The build copies the INF/SYS/CAT/DLL hashes
that were actually injected into `build-manifest.json`.

## Other OEMs

WinPE only carries the in-box network drivers. A node whose adapters have no in-box driver shows no address in the network status
block. Adding drivers for other hardware:

1. Boot Beacon on the node, open the menu option 7 console and list the adapters without a driver:
   `pnputil /enum-devices /problem` (note the `PCI\VEN_xxxx&DEV_xxxx` hardware IDs).
2. Get the driver package for **Windows Server 2022 / Azure Stack HCI OS x64** from the vendor or the OEM's Solution Builder
   Extension, or export it from a provisioned node: `Export-WindowsDriver -Online -Destination C:\drivers`.
3. Keep only the network drivers (`.inf`, `.sys`, `.cat`, and any DLLs the INF names). Use WinPE-compatible, signed (`.cat` present) packages.
4. Pass the folder: `.\src\Build-WinPEImage.ps1 -DriverPath C:\drivers` (searched recursively; the DriverVer of each INF is printed in the build log).
5. Optionally keep the set in the repository under `drivers/<oem>-<model>/` with its source noted in `scripts/New-DriverManifest.ps1 -SetSource`, then regenerate the manifest.

The default `-DriverPath` is `drivers/dell-ax`; to build without any added driver pass `-DriverPath ''`.
